# WEB-10 — Operator browser acceptance scenarios

**Status:** PENDING; testing in real Firefox and Chromium is required. [App](https://remappingbridge.github.io/) · [Automated browser test page](https://remappingbridge.github.io/tests/) · [Published site source](https://github.com/remappingbridge/remappingbridge.github.io/tree/main).

1. **GitHub Pages / HTTP:** load the live app without sign-in in a fresh private window; with browser Network/Console open, reload and confirm `index.html`, CSS, all 8 app JS modules, `tests/index.html`, its fixture and runner all return successful responses without 404 or uncaught JavaScript exceptions.
2. **Automated parity:** open `/tests/` in **Firefox** and **Chromium**. Expected: the summary says **all checks passed**, with an increased dynamic total after WEB-10's 45-source-screen assertions. Report the exact failing test name and browser if not.
3. **Actual screen catalog:** on the simulator, expand **Inspect all 45 firmware screens** and sweep the 45 entries, including all six COMBINATIONS and all five SHORTCUTS groups. Exactly 240×240 source bitmap, no broken magenta titles or overlapping text.
4. **Demo semantics:** click **Searching First Mouse** → `SEARCHING FIRST MOUSE`; **First Mouse Connected** → `FIRST MOUSE CONNECTED`; **Home Connected** → interactive HOME. Create an actual saved *virtual* mouse and repeat all three; no demo may mutate that inventory.
5. **HAT geometry and scrolling:** keep the HAT visible while scrolling through the panels. `REMAPPINGBRIDGE` upper-left, yellow-dot `VIRTUAL DEVICE` lower-left, `PICO 2 W/LCD 240 × 240/9 HAT CONTROLS` bottom-right, A/B/X/Y inside the LCD-height vertical column.
6. **Zoom and responsive:** Firefox/Chromium at 100%, 150%, 200% and (where usable) 300% or 400% zoom. Test notebook 1366px, 2K/HiDPI, mobile portrait ~320px and landscape ~768px; no HAT cut off or inaccessible actions. Note browser and zoom if geometry fails.
7. **Mobile touch + keyboard:** on narrow touch layout ensure all 9 LARGE TOUCH CONTROLS have >=44 CSS-pixel targets; on desktop use arrows, Enter/Space, and A/B/X/Y with focus rings. Typing mouse names must not trigger accidental HAT keyboard commands.
8. **Initial connection:** Pair a new virtual mouse, press *Complete Successfully*. The first connection must show `FIRST MOUSE CONNECTED`, and following Home Connected must show the new mouse in HOME. No physical Bluetooth is used.
9. **Two-column workflow:** Saved virtual mouse panel is on the **left**, New virtual mouse name panel on **right**. Each start button shares a row with its own input/select; outcomes are directly below within each panel. At small width the panels stack and remain usable.
10. **Mode-scoped outcomes:** start Pair New, check only pair success/failure enabled; simulate failure and retry. Start Search Saved, check only the saved-search outcomes enabled. Success reconnects the same saved ID, failure keeps its profile and bond.
11. **Timeout, cancel, reboot:** run Advance to Timeout, Cancel Pending and Reboot Virtual Device; verify Retry screens and no accidental new bond, ghost result, or loss of unrelated saved mice.
12. **Multiple mice/persistence:** create two saved virtual mice with different names and profiles, reload the browser, reconnect each. The correct profile/H/V DPI/rotation/shortcuts persist only for their own mouse; no duplicated IDs.
13. **Custom + Modifier/MNT-12:** Passthrough and draft Custom do **not** activate Modifier Shortcuts cyan. Only applied CUSTOM plus one applied MODIFIER enables cyan; verify without and with a saved assignment.
14. **MNT-13 selection:** each focused option has exactly one `|` at column 1 (visual left); for two-line COMBINATIONS it appears on the *second* line, not the label. No extra marker in Help/other non-selectable rows.
15. **Shortcut and Movement:** test all 12 modifier combinations / 30 shortcut names; confirm one unavailable modifier-mapped slot; apply/reset a selected assignment. Set horizontal 2×, vertical 0.75× and rotation 90°, then Reset Movement and verify only Movement defaults restored.
16. **Lock and Help:** press Y on an interactive screen: actual LCD black. Press/release one HAT key to unlock and return to the correct virtual screen; X and B Help/Back stay source-conformant. No obsolete brightness/density UI appears anywhere.
17. **Factory reset safety:** with saved virtual mice, click Factory Reset Virtual Mice and **Cancel** first: all data survives. Confirm the second time: saved count zero, disconnected and `SEARCHING FIRST MOUSE`. Reload: no ghosts.
18. **Inspector + evidence:** run all eight isolated scenarios. Repeated scenario hashes must agree and never mutate browser saved virtual mice. Click or keyboard-select a glyph, Copy Reference, export JSON/TXT/240×240 PNG locally, and inspect the actual downloaded files. Network panel should show no upload/telemetry.
19. **Private/offline/local:** verify no external CDN, log-in dialog, framework build, service worker or backend call; source files may also be opened from a local static checkout via `file://` or optional `python3 -m http.server 8000`. The physical Pico, BLE/HID and UF2 must remain untouched.
20. **Regression storage isolation (mandatory):** before opening `/tests/`, create one distinctive virtual mouse and save a Custom/Movement setting in the *real* `/` app. Run the complete browser test page including its Factory Reset test, then return to `/` and reload. Expected: the original saved mouse and settings remain intact; test page starts at zero synthetic mice irrespective of actual inventory.
21. **Record acceptance:** report actual browser/version, screen width and zoom, final `X/X checks passed` or names of failures, and whether direct HTTP, clipboard/download and mobile checks passed. Explicit operator acceptance is needed before WEB-11.

**Do not confuse deployment success or simulated V8 tests with human Firefox/mobile execution. WEB-10 remains pending until operator accepts it.**
