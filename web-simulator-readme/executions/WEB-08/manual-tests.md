# WEB-08 — Numbered production-browser acceptance tests

**Status:** OPERATOR ACCEPTANCE PENDING. **Only production browser**, no Debian/local server, firmware flashing, npm or physical mouse connection. Open https://remappingbridge.github.io/ and https://remappingbridge.github.io/tests/.

1. **Direct application, no institutional header:** open the simulator. **Expected:** sticky physical HAT is the first application element; no extra editorial website header, navbar, site hero or footer.
2. **Preserve WEB-07 physical HAT:** inspect the panel. **Expected:** REMAPPINGBRIDGE top-left, yellow-dot VIRTUAL DEVICE bottom-left; joystick left, square Gentle LCD center, vertical A/B/X/Y right, Pico/LCD/HAT specs far right. Source magenta/cyan/yellow tones still distinguish firmware roles.
3. **Fixed Gentle and no separate backdrop:** verify the LCD background is dark magenta #300c39 and there is **no LCD BACKGROUND selector**. **Expected:** original 45 source screens, 9×21 text and `|` focus still operate.
4. **Brightness endpoints:** in **LCD appearance** move the brightness slider slowly **100 → 50 → 0 → 100%**. **Expected:** numeric requested and effective readouts follow; 50% visibly dims Canvas; 0% makes it completely black; returning to 100% restores it without resetting the firmware screen. No value exceeds 100%.
5. **Brightness and independent navigation:** at 30% brightness, use the HAT joystick and switch pages. **Expected:** navigation remains fully functional; the dimming affects only LCD appearance, not the physical joystick/buttons or Virtual Mouse Lab.
6. **Lock/Unlock remembered brightness:** choose **37%**, enter Connected demo, press/release **Y**. **Expected:** LCD is black and effective brightness reports **0%** while the slider still remembers **37%** (temporarily disabled). Release one HAT control to unlock. **Expected:** LCD Home returns at **37%** without triggering that control's usual action.
7. **Persistence after refresh:** choose brightness **63%** and density **Spacious**, reload the browser page. **Expected:** 63% and Spacious return if localStorage is enabled; a restricted browser instead clearly says memory-only, never pretends durable storage.
8. **Density variants:** switch **Compact → Standard → Spacious**. **Expected:** spacing of lower simulator sections changes clearly while the square LCD size, 240×240 source pixel content, brightness and actual virtual mouse profiles remain unchanged.
9. **Keyboard and visible focus:** Tab through the brightness slider, density selector, scenario buttons, Virtual Mouse Lab inputs, buttons and HAT. **Expected:** strong visible focus outline, native keyboard slider adjustment, labels spoken/readable; no element requires a mouse pointer.
10. **Small mobile screen / finger targets:** use a **320px** wide browser viewport/mobile portrait. **Expected:** the compact physical HAT stays recognizable and a separate **LARGE TOUCH CONTROLS** panel appears containing five joystick positions and A/B/X/Y, each **44×44 px minimum**. Use touch keys to navigate Home/Help/Back/Lock; they act on release and do not cause duplicate actions.
11. **Responsive / sticky / zoom:** repeat scrolling at **320px, 768px and 2K** screen widths, and Firefox **150%/200% zoom**. **Expected:** sticky HAT stays visible while lower controls scroll; no unusable horizontal overflow, inaccessible input panel or LCD obscured by corner labels. Lower settings are arranged vertically on narrow screens.
12. **Reduced-motion and HiDPI:** enable system **Reduce Motion** and revisit the app; inspect on a HiDPI laptop or zoom the canvas. **Expected:** button transitions respect reduced-motion; source bitmap pixels remain crisply square (no system-font replacement) and focus/press states remain clear.
13. **Regression: saved mouse operations and shortcuts:** pair/connect a virtual mouse, select Custom Modifier, assign/revisit/reset a shortcut, try Movement. **Expected:** prior WEB-05/06/07 flows work and the new display controls do not alter any saved profiles or emit host HID.
14. **Native browser automated suite:** open https://remappingbridge.github.io/tests/. **Expected: `226/226 checks passed.`** If FAIL, copy exact English test name and browser/zoom context. Isolated 226/226 alone does not count as live browser acceptance.
