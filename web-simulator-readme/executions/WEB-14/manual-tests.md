# WEB-14 — Manual installation and release acceptance scenarios

**Status: PENDING.** Source [GitHub README](https://github.com/remappingbridge/remappingbridge#readme), [latest release](https://github.com/remappingbridge/remappingbridge/releases/latest) and official [Pico BOOTSEL documentation](https://www.raspberrypi.com/documentation/microcontrollers/pico-series.html).

1. **Accepted first impression:** verify README still begins with the exact approved **OPEN LIVE SIMULATOR** and UF2 download links, and the Pico 2 W/Waveshare hardware photographs. Do not reintroduce the previously rejected “Curious?”/large static simulator preview.
2. **Real current release:** inspect the current latest published GitHub release at review time. If it is **v3.2.4**, check UF2 filename `remappingbridge-v3.2.4-pico2w.uf2` and `SHA256SUMS.txt` actually appear together as official assets (953,344 bytes UF2). If a newer release was published, STOP and require a version-link documentation update **within WEB-14** before acceptance.
3. **File hashes:** download both assets into the same clean directory. Compare the resulting SHA-256 with `56d2eeaf96b2579e34b85333274a4bf1652b6bf33384d1b275eee36aa06f88f2` and `SHA256SUMS.txt` content. Use Linux `sha256sum -c SHA256SUMS.txt`, macOS `shasum -a 256 -c SHA256SUMS.txt`, or PowerShell `Get-FileHash -Algorithm SHA256 .\remappingbridge-v3.2.4-pico2w.uf2` (compare manually). **No checksum mismatch is acceptable**. Where any OS is unavailable, do not claim it was physically tested.
4. **Board identification:** the procedure targets **Raspberry Pi Pico 2 W / RP2350 + BLE**, not Pico/Pico W/Pico 2 without W, not a Linux 40-pin HAT and not an external USB receiver.
5. **Cable/power-off:** use a tested Micro-USB cable that carries data; disconnect USB before installing/adjusting any HAT headers; do not attach or remove an energized display.
6. **BOOTSEL:** with Pico unplugged, hold the **physical BOOTSEL** button while connecting USB data to computer; release after the bootloader drive appears. Do not hold joystick press in place of Pico BOOTSEL.
7. **Pico 2 volume names:** be prepared for **RP2350** or **RPI-RP2**. Neither is a drive to format, partition or overwrite with arbitrary files.
8. **UF2 file only:** copy the verified `.uf2` file, not the checksum text or a ZIP. Do not run a direct disk writer such as `dd` against the bootloader volume.
9. **Automatic reboot:** copying UF2 finishes, then the temporary USB mass-storage volume automatically disappears and board restarts in firmware mode. This disappearance is expected, not a hardware disconnect fault.
10. **Post-install behavior:** if real hardware is available and compatible BLE HOGP mouse is on hand, confirm firmware LCD starts, mouse can pair, USB HID output reaches compatible host. If user opts not to flash a physical Pico for a documentation gate, simply verify documented steps against official manufacturer instructions rather than invent physical success.
11. **Normal update safety:** nowhere does README advise `flash_nuke` as the normal update procedure. Don't format RP2350/RPI-RP2, reset bonds, or promise version-independent profile preservation. Preserve existing and compatibility warnings, especially v3 → v2 downgrade.
12. **Missing drive troubleshooting:** README should first mention board type, verified data cable, correctly held BOOTSEL and USB host port; never suggest erasure as the first fix.
13. **Future release link policy:** direct URL tag **v3.2.4** is version-locked; separately verify `/releases/latest` works. Verify README text explicitly tells maintainers to update filename, digest and release links when new firmware publishes; no false permanent latest-UF2 file URL.
14. **Structure and readability:** on desktop and mobile/large zoom, top hero stays compact, installation steps readable and linear, copyable commands appear only in relevant OS-specific sections, and installation info does not hide behind an obscure technical appendix.
15. **Scope and authorization:** [firmware PR #51](https://github.com/remappingbridge/remappingbridge/pull/51) changes **only README.md**, no new firmware tag/UF2/build scripts/site HTML; [planner evidence PR](https://github.com/remappingbridge/planner/pulls) stays draft and WEB-15 remains unopened until operator explicitly accepts WEB-14.

Record host OS, actual board name, and if physical test was performed the BOOTSEL drive label and hash comparison result.
